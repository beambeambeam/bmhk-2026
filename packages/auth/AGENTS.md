# Authentication package

This package owns the Better Auth server configuration. `src/index.ts` is the
server authentication source of truth.

## Change-impact rule

When changing `src/index.ts`, inspect every consumer before finalizing the
change. At minimum, check:

- `packages/client/src/auth-client.ts` for matching client plugins and inferred
  endpoint types.
- `apps/server/src/modules/auth/auth-reader.ts` for explicit session mapping.
- `packages/api/src/core/auth.ts` for the public `ApiUser` and `ApiSession`
  contract.
- `apps/server/src/modules/auth/auth.module.ts` and `apps/server/src/app.ts`
  for route handling, methods, CORS, and trusted origins.
- `apps/web/src/middleware/auth.ts`, `apps/staff/src/middleware/auth.ts`, and
  both apps' auth routes and forms for UI and navigation assumptions.
- `packages/db/src/schema/auth.ts` and `packages/db/src/migrations/` for
  database changes.
- Authentication tests and environment validation under `packages/env/`.

Do not assume Better Auth type inference updates every boundary correctly.
Keep server plugins and client plugins synchronized, map nullable values
explicitly, and preserve backwards compatibility for existing sessions and
users.

## Plugin and endpoint guidelines

- Review plugin documentation and generated schema before adding or changing a
  plugin.
- Review every new endpoint for authentication, authorization, CORS, method,
  enumeration, and rate-limit implications.
- Do not expose secrets, password material, session tokens, or raw auth errors
  in logs or API responses.
- Keep email/password behavior stable unless the change explicitly requires a
  migration of client flows.
- Update client methods, API contracts, server readers, and tests together when
  changing returned user or session fields.

## Database workflow

`packages/db/src/schema/auth.ts` is generated by Better Auth. Never edit it
manually. After an auth configuration change that affects schema:

```sh
bun run --filter @bmhk-2026/auth auth:generate
bun db:generate
bun db:migrate
```

Review generated SQL and metadata. Keep migrations additive and reversible
where practical. Consider existing rows, nullable values, unique constraints,
rollback impact, and deployment ordering before applying a migration.

## Verification

Run relevant checks from repository root:

```sh
bun run --filter @bmhk-2026/auth auth:info
bun run check-types
bun run test
bun run check
bun run build
```

For auth behavior changes, add tests for success, invalid input, unauthorized
access, missing optional fields, and any disabled or protected endpoint.

## Seed workflow

`bun run db:seed:auth` owns local Better Auth accounts only. Do not add
registration fixtures to this command.
