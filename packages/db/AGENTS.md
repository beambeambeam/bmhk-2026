# Database package

This package owns the PostgreSQL schema, Drizzle client configuration, and generated migrations.

## Schema changes

1. Update the relevant schema file under `src/schema/`.
2. Export new schema modules from `src/schema/index.ts` when needed.
3. From the repository root, generate a migration:

   ```sh
   bun db:generate
   ```

4. Review the generated SQL and Drizzle metadata under `src/migrations/`.
5. Apply the migration:

   ```sh
   bun db:migrate
   ```

6. Run relevant type checks and tests before finishing.

Keep schema changes and their generated migration files in the same change. Prefer generated migrations over `db:push` so schema history remains reviewable and reproducible. Never modify an already-applied migration; create a new migration instead.

## Better Auth schema

`src/schema/auth.ts` is generated by Better Auth. **Do not edit this file manually.**

When authentication tables need to change, update Better Auth configuration in the auth package, regenerate `src/schema/auth.ts` through Better Auth, then run the standard database workflow:

```sh
bun db:generate
bun db:migrate
```

Review generated authentication schema and migration output, but make fixes at their source rather than patching generated code.

## Database conventions

- Use Drizzle schema definitions as the source of truth.
- Use PostgreSQL-compatible types and constraints.
- Give indexes and constraints stable, descriptive names.
- Define nullability, defaults, references, and delete behavior explicitly.
- Add relations when application queries need typed relational access.
- Avoid destructive schema changes unless data migration and rollback impact have been considered.
- Never include secrets or local connection strings in committed files.
